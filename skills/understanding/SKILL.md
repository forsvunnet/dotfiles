# Reach a common understanding first

Before doing any work, stop and build a shared understanding of what the user
actually wants. Do not write code, edit files, or take action until you and the
user agree.

## Steps

1. **Restate the request** in your own words: what you believe the user wants,
   why, and what "done" looks like.

2. **Surface the gaps.** List your assumptions, the parts you are unsure about,
   and any ambiguity in scope. Distinguish established fact from your inference.

3. **Ask before guessing.** When a real decision depends on the answer, ask the
   user. Write the question as plain text, then list suggested answers as a
   numbered list so the user can reply with a number. Keep it to one or two
   simple questions at a time. Do not ask about things with an obvious default.

4. **Confirm.** Wait for the user to agree or correct you. Only once the
   understanding is shared do you proceed with the work.

## Notes

- If the request has a better framing, say so now, before agreement.
- If the request is wrong or low quality, flag it directly, then proceed if the
  user confirms.
- Do not present a wall of text. Introduce ideas one at a time.
